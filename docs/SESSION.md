# 星座の配置と保持セッション

星をみるひとAPIの結果から選んだIDと、送信に同意した同じ地点を使い、認証付き `POST /api/project` を呼ぶ。
準備ボタンを押した時点のUTCで固定カタログを計算する。星APIの日時仕様とは別契約であり、時刻の一致は未確認と表示する。
代表方位や opaque な drowing から星を作らない。API失敗をfixtureで置き換えない。

## 手順

1. 星APIから星座を選ぶ。
2. 撮影に別途同意し、手首推定を開始する。座位/立位、使う手を選んで楽な範囲を記録する。
3. 「配置を準備する」で投影・配置を確認する。ID、時刻、座標系、ミラー状態、固定カタログ出典・版・ライセンスを照合する。
4. 配置可能なら「配置した星座を開始する」を押す。カタログ順、または個別送信同意でCodexが計画した検証済みの順序で実行する。Jev助言は未接続。
5. 選んだ手の現在点を輪に重ねる。新しいセンサー時刻による800msの保持で実測点を確定する。全対象のcaptureでのみ完成する。

投影で対象外となった星の数、配置倍率、UTC時刻を表示する。
12個を超える投影、重なり、近すぎる目標、未観測の目標付近は拒否し、星を勝手に間引かない。
一様な縮小と平行移動のみ。観測された画像内の位置を使うもので、物理的な到達・安全を保証しない。
目標は非ミラー正規化画像座標で保持し、表示だけを鏡像にする。輪の半径は各軸4.5%で、判定の正規化距離に対応する。

## 中断と破棄

RequestSessionが準備処理の世代とAbortを管理する。条件変更後の古い応答は配置を復元しない。
計測の消去・やり直し・姿勢/手/映像寸法の変更・追跡ロストで配置を無効にする。
停止・Esc・タブ非表示は通信、カメラ、推定、実行を停止する。保持を継続せず、再計測・再準備・本人の開始操作を必要とする。
停止時の確定点は静止表示する。星座/地点/トークンの変更、位置同意撤回、配置消去では以前の星座表示を消す。撮影同意撤回でも全描画記録を消す。
手首の画像座標や撮影映像は送信・保存しない。投影POSTはid/lat/lng/atだけ。

## 検証

追加の単体4件で、ID/時刻/出典/座標契約、星数上限、保持進捗、実測captureと元の線を確認。
ブラウザー12件はAPI応答・手首・ビットマップ・フレーム時刻を合成したfixture。
3星の通し完了、リセット、ロスト、姿勢/位置変更、同意撤回、Esc、非表示、古い応答破棄、投影異常、スマートフォン幅を確認する。
実Three.js/WebGLで描画し、PC完成図とスマートフォンの目標表示を画像確認する。
`session-fixture-*.png` はテスト成果物で、実API/実人体の成功証拠ではない。

セルフレビューでは非同期の再開競合、旧セッションの描画、出典照合、送信ペイロード、鏡像/保持座標を点検。
星座・地点変更で古い完成図が残る問題を修正し、固定出典のcommit/license照合を追加した。
別担当者の独立レビューは未実施。

実APIトークン、星API時刻整合、実人体受入、AI生成正常系/Jev助言、公開用認証、Cloud Run検証、デプロイは未完了。
追加パッケージはなく既存lockfileを維持する。

## 合成UI試験の時刻制御（#28）

星座接続後のWindows/Edge全体試験は55/56成功。既存poseのno_person試験で、明示再開後に映像が150ms以内に届かずframe_gapへ遷移した。試験再実行だけで済ませず、pose/reachの合成Worker試験に共通の制御時計・33msフレーム・合成bitmapを導入した。
実SDK/実合成動画を使う起動・人物不在・モデル失敗の3試験は変更せず、リトライや製品の150ms条件も変更しない。合成フレームを止め、200msの経過でframe_gapになるブラウザー試験を追加した。逆行・古い応答・欠落の単体試験も維持する。

ローカル検証結果: npm run check（108件＋本番ビルド）成功。Windows/Edgeの全57ブラウザー試験が成功し、#28の再発ケースも解消した。PC完成図とスマートフォンの目標・常設停止を目視確認。目視で左手実行中の手選択欄が右手のままになる点を見つけ、表示と消去時の準備状態を同期した。最終差分の画面試験とLinux CIをPRで確認する。
