# 光の軌跡と確定した星

画面の「手の軌跡を、光にする。」から、ローカル推定した片手の軌跡をThree.jsで表示する。
撮影同意・カメラ・手首推定の開始後、本人が描画を開始する。身体を伸ばす目標や移動指示は出さない。
軌跡だけを試す表示では星を確定しない。星API選択・投影・計測範囲からプログラムを準備した場合は、保持した実測点で星を確定する。[セッション仕様](SESSION.md)を参照。AI振付・助言の統合は#15に残る。

## 計測と確定

core/trace.jsのConstellationTraceはDOM・ネットワーク・Three.jsに依存しない。
プログラムを渡した場合は既存HumanRuntimeによる800ms以上の保持判定からだけcaptureを生成する。
描画側にcapture判定を持たせず、実測座標x/y、計測時刻at、確定時刻capturedAtを保持する。
未確定の目標は別レイヤーへ描く。確定線は元の星座線の両端がcaptureされた場合だけ生成し、途中の未確定点を飛び越さない。

軌跡はセンサー時刻で直近4秒、最小33ms間隔、最大120点。プログラムは最大12星、線は最大66辺。
軌跡の明るさは時刻に基づく。軌跡の長さや推定confidenceを保持・到達・安全の判定に用いない。

不正値、別の手、重複/逆行/150ms超の古い計測、フレーム間隔、時計逆行、追跡ロストで停止。
50ms間隔の監視も新しい計測がない場合に停止する。停止後に届いたフレームは追加しない。

## 停止と消去

- 停止・Esc・非表示・追跡ロスト：新しい蓄積を止め、現在点を消して過去の点を静止する。
- 明示的な再開：軌跡は新しく描く。coreの振付付き再開では既存captureを維持し、現在の保持時間をやり直す。
- 軌跡の消去・使う手の変更・映像寸法の変更・撮影同意の撤回：全記録を消す。
- ページ離脱：全記録、イベント、監視、ResizeObserver、GPUリソースを解放する。
- 完了：追加captureや自動再開は行わず、リセットまで確定結果を維持する。

実測点はメモリだけに置き、外部送信・保存・ログ出力をしない。GPUバッファも消去時にゼロ埋めする。

## 描画と失敗

[Three.js WebGLRenderer](https://threejs.org/docs/#WebGLRenderer)とインストール済み0.180.0の実装を確認。
依存は既存lockfileの版を使用し、MITライセンスをthird-party/THREE-LICENSE.txtに同梱する。

OrthographicCameraの画像平面へ描画し、奥行きは0。時間を奥行きや物理距離へ偽装しない。
coreは非ミラー画像座標、描画だけxを1-xへ変換し、鏡像カメラと揃える。映像と同じ縦横比で表示する。
目標・現在点・軌跡・確定点・確定線は別の固定容量BufferGeometryを使い回す。
通常は計測更新時、停止中はリサイズ時だけ描画する。常時回転や点滅はしない。
DPRは最大2、長辺の描画バッファは2048pxを上限にする。

WebGL初期化失敗・描画失敗・context lossは固定文言で通知し、描画とカメラ/推定を停止する。
復旧は本人のカメラ/推定/描画開始操作が必要。失敗をモックや別の成功表示に置き換えない。

## 試験の区分

単体試験は既知の保持入力・欠損線・座標・時刻・停止・長時間入力・GPUバッファ/解放を検証する。
ブラウザー試験は合成カメラ・合成手首座標・合成bitmapと制御した時計、実Three.js/WebGLを使う。
実時計での初期試験ではGPU負荷による150ms停止も発生した。停止閾値は変更せず、UI契約試験の時計を固定した。
実動画のデコード/タイミングと実SDK推論の試験は既存pose.spec.jsに残し、実機性能は未確認。
確定した星の描画はe2e専用ハーネスがHumanRuntimeへ合成座標を渡して確認する。
ハーネスはテスト時のrouteのみで配信し、本番ビルドへ含めない。実カメラや実参加者の検証とは区別する。
