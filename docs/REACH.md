# 動かせる範囲の計測（Issue #11）

## 今回の範囲

ローカル推定から選択した手首の位置を受け取り、座位/立位の自己申告と一緒に画面上の動きを記録する。
配置変換はcoreの純粋関数として実装・合成入力で検証した。恒星カタログの投影と、カタログ順で実行する[セッション](SESSION.md)に接続済み。AI振付・実人体受入は未完了。
星APIの代表方位を恒星位置に見立てたり、試験用の星座を製品画面で表示したりしない。

## 操作と中断

1. 撮影に同意してカメラを開始し、手首の推定を開始する。
2. その場で楽な姿勢（座位/立位）と、動かす手（左/右）を選ぶ。移動、走行、閉眼、最大限の伸展は要求しない。
3. 「楽に動かせる範囲を計測する」を押し、小さくゆっくり動かす。3秒以上を目安に本人の操作で確定する。
4. 短すぎる/狭すぎる場合は理由を表示して未確定のままにする。無理に広げず、中断またはやり直せる。
5. 計測中断、姿勢・手の変更、追跡ロスト、150msを超える古い計測、重複・逆行時刻、映像寸法変更で記録を消去する。
6. 常設停止、Esc、非表示、同意撤回ではカメラ・推論の停止に連動して消去する。再開後も自動復元しない。

片手を動かす操作には対応するが、現行PoseSourceは両手首の可視性を必須にしている。
片手だけが映る/もう一方の手を検出できない場合の推論対応は未実装。検出精度・安全性・到達可能性の保証はしない。
身体やカメラの位置が変わったことを自動判定しない。同じ映像寸法でも配置を変えたら手動で計測し直す。

## 計測契約

- 非ミラーの正規化画像座標とWindow単調時刻のみ。物理距離、深さ、世界座標は使わない。表示だけを鏡像化。
- 連続した新しい計測で3秒以上、30点以上を必要とする。記録間隔は50ms以上、開始から最大30秒・601点。
- 確定後は記録点と記録時間を固定し、推定の継続と映像寸法を監視する。
- 位置はメモリ上のみ。送信、永続保存、ログ出力、localStorageへの保存をしない。SVGの記録点も消去する。
- 各軸の上下5%を除き、0.02内側へ寄せ、ProgramV1の0.1〜0.9に収めた範囲を使う。
- 幅・高さのどちらかが0.08未満なら未確定。これらは画面配置上の設計値であり身体安全の閾値ではない。

## 配置変換の契約

fitConstellationToReach(constellation, reach) は、投影済みと確認されたID付き画像座標と計測結果を受け取る。
入力座標は同じ画像座標の定義・縦横比を使う必要がある。別の画像寸法へ流用しない。

- 元の星ID・順序・点数を保持し、選択した一方の手を使う。
- 平行移動と一つの等方縮小率のみで正規化画像内の形を保つ。拡大・個別の座標押し込み・反転・星の削除をしない。
- 中央配置で最大20段階の縮小を試す。配置可能な全変換を探索するものではなく、保守的に拒否する場合がある。
- 各目標の距離0.025以内に記録点が3点以上あり、最初と最後の間隔が200ms以上あることを要求する。
  外枠の内側というだけでは採用しない。記録のない空白や単発の外れ値を到達範囲とみなさない。
- 異なる目標が0.10未満に近づく場合は拒否する。保持は800ms、許容差0.045で既存の決定論的runtimeに渡せる。
- この幾何検査は目標点の観測根拠を確認するだけで、身体の安全・無理のなさ・移動経路を判定しない。
- 返値のprogramだけで実行しない。#15で同じ計測セッションが有効なことを確認し、中断時は計画も無効化する必要がある。

拒否は固定reasonで返す。invalid_constellation / invalid_calibration は入力不備、
narrow_range は計測範囲不足、overlapping_stars / too_close は星の重なり、
unobserved_targets は記録付近へ形状を保って配置できなかったことを表す。
縮小できた場合はscaleとreducedを返す。#7/#15統合時に理由と縮小を参加者へ表示する。現時点の画面は計測理由のみ表示する。

## 検証と残条件

- 単体：左右選択、座位/立位、短い/狭い/直線状の計測、不正値、時計、追跡ロスト、映像寸法、
  容量制限、確定時の記録固定、形状とIDの維持、未観測点/外れ値/重なり拒否、HumanRuntimeへの契約。
- ブラウザー：合成カメラ・合成手首座標・テスト用フレーム通知で計測・確定・やり直し、姿勢/手の変更、停止・同意撤回・ロスト・非表示、PC/スマートフォン幅。
- 実カメラ・参加者による操作、負担、計測範囲の適切さは未確認。fixtureの成功を実人体の検証と扱わない。
- #11は投影・実セッション接続と同意した参加者の確認が残るため、完了扱いにしない。
- 外部APIや依存パッケージの変更はない。既存lockfileを維持し、CIのnpm ciで検証する。
