# カメラの同意・停止と検証（Issue #9）

## 実装範囲

カメラ映像を端末内のvideo要素で表示する。音声は要求せず、映像の送信・録画・保存を行わない。
撮影同意は位置送信同意から独立し、APIの設定がなくても利用できる。
手首のローカル推定を別ボタンで開始する機能は#10で追加。[POSE.md](POSE.md)を参照。星座への身体誘導は未実装。

- 同意チェックと開始ボタンの操作後だけgetUserMediaを呼ぶ。
- 開始要求は同時に1件。許可待ちの間も停止できる。
- 停止、Esc、タブ非表示、pagehide、同意撤回で全トラックを停止し、video.srcObjectを解除する。
- trackのended/mute、streamのinactiveでも停止し、unmuteによる自動復帰はしない。
- 停止・破棄後に許可が返っても、そのストリームを表示前に解放する。
- 許可ダイアログ自体はプログラムからキャンセルできない。要求が残っている間は再要求を抑止し、画面に説明する。
- 映像再生の待機は停止で解除し、8秒で失敗する。開始直後の一時的なmuteは再生開始まで待って判定する。
- pagehideで撮影同意を解除する。履歴復帰後も再同意と開始操作が必要。
- エラー名を分類して固定文言を表示する。生のエラー本文・デバイス名・映像はログに出さない。
- NotReadableErrorは機器使用中を含む読み取り失敗であり、使用中と断定しない。
- プレビューの左右反転はCSS表示だけ。計測座標へ反転を適用したり、世界座標とみなしたりしない。

## 自動試験

`npm run check`のCameraSession試験は偽のトラック・videoを注入する。
同意前、非表示、安全なコンテキスト外、権限拒否、機器なし、読み取り失敗、
遅延した許可・拒否、再生失敗、起動時mute、途中切断、停止・破棄、再開を検証する。

`npm run test:browser`はPlaywrightの専用ブラウザーで
`--use-fake-device-for-media-stream`と`--use-fake-ui-for-media-stream`を使用する。
さらにuse-file-for-fake-video-captureでe2e/setup.jsが生成する合成パターンをループ再生する。実カメラ・マイクは開かない。拒否や機器なしはgetUserMediaのテスト用スタブ。
タブ非表示とpagehide/pageshowはイベントを注入した経路試験であり、実機のOS・ブラウザ挙動の確認ではない。
録画・traceは無効。保存画像は合成映像と架空の試験入力のみ。

## 実機確認（未実施）

実カメラを使う人がローカル画面で撮影に同意して実施する。映像や機器識別情報を記録へ添付しない。

1. HTTPSまたはlocalhostで開き、同意前にカメラ使用表示がないことを確認する。
2. 同意して開始し、ブラウザの許可表示で拒否する。画面の説明と再試行を確認する。
3. 許可して映像を表示し、停止・Esc・他タブへの切り替えをそれぞれ確認する。
4. 他アプリがカメラを使用していない状態で、停止後のブラウザ使用表示・カメラランプが消えることを確認する。
5. 再開は明示操作のみであること、同意撤回・ページ離脱・戻る操作後も自動開始しないことを確認する。
6. 外付けカメラがあれば途中切断を確認する。映像を送るネットワーク要求がないことを確認する。
7. ブラウザ・OSの版、各項目の成否、未確認項目だけをIssue #9へ記録する。

他アプリも同じカメラを利用している場合、こちらのトラックを停止しても機器全体は停止しないことがある。
実機確認が完了するまでIssue #9を完了扱いにしない。
